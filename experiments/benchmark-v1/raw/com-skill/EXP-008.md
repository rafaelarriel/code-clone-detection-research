# Relatório de detecção de clones de código

## Escopo e limitações

- Escopo completo: todos os 7 arquivos sob src/, exclusivamente.
- Linguagem: Python.
- Revisão: indisponível; o diretório não contém repositório Git acessível.
- Exclusões: nenhum arquivo dentro de src/; arquivos fora desse diretório não foram acessados.
- Testes: não executados, conforme solicitado. A análise é estática e somente leitura.
- Achados: 11 relações (incluindo grupos de pares sobrepostos). T1: 2; T2: 3; T3: 3; T4: 3 hipóteses.

## Achados

### CLONE-001 — normalização de nomes

- Classificação: T1, para o corpo das funções.
- Estado: clone estrutural confirmado.
- Pares:
  - src/formatting.py, normalized_person_name, linhas 5–7 ↔ normalized_customer_name, linhas 11–13.
  - normalized_person_name, linhas 5–7 ↔ normalized_email, linhas 23–25.
  - normalized_customer_name, linhas 11–13 ↔ normalized_email, linhas 23–25.
- Abrangência: apenas o corpo; as declarações das funções possuem nomes distintos.
- Evidência: os três blocos verificam None, retornam "" e, caso contrário, aplicam strip().lower() em value.
- Justificativa: sequência de tokens idêntica, sem diferenças além da posição.
- Limitações/falsos positivos: nomes de pessoa, cliente e e-mail podem evoluir com regras próprias — por exemplo, e-mail pode não dever ser normalizado com as mesmas regras.
- Confiança: Alta.
- Sugestão: extrair uma função privada, por exemplo _normalize_text(value), somente se a política de normalização for intencionalmente comum. Manter os wrappers nomeados preserva a semântica do domínio.
- Verificações propostas: None, string vazia, espaços laterais, maiúsculas, Unicode e e-mails com caracteres relevantes.

### CLONE-002 — soma idêntica de unidades

- Classificação: T1, para o corpo.
- Estado: clone estrutural confirmado.
- Local A: src/inventory.py, total_stock_units, linhas 5–8.
- Local B: src/inventory.py, available_units, linhas 19–22.
- Abrangência: corpo inteiro; as funções diferem apenas no nome declarado.
- Evidência: inicialização com zero, iteração por entries, acumulação de entry["units"] e retorno de count são idênticos.
- Justificativa: código literalmente igual.
- Limitações/falsos positivos: “total” e “available” podem representar regras de negócio que devem divergir futuramente; no estado atual, não há filtragem ou reserva de estoque que justifique a separação.
- Confiança: Alta.
- Sugestão: manter uma função de cálculo compartilhada e wrappers semânticos, ou eliminar uma delas caso ambas tenham exatamente o mesmo contrato.
- Verificações propostas: lista vazia, valores negativos, ausência da chave units e valores numéricos não inteiros.

### CLONE-008 — contagem com limiar distinto

- Classificação: T3.
- Estado: clone estrutural confirmado.
- Local A: src/analytics.py, positive_count, linhas 4–9.
- Local B: src/analytics.py, count_nonnegative, linhas 16–21.
- Abrangência: função inteira.
- Evidência: ambas percorrem números e incrementam contador sob condição; o predicado muda de number > 0 para number >= 0.
- Justificativa: estrutura copiada com statement condicional alterado; > e >= não são mera renomeação.

- Verificações propostas: sequência vazia, apenas zero, negativos, positivos, geradores e valores que não suportem comparação.

### CLONE-009 — subtotal iterativo versus sum

- Classificação: T4.
- Estado: hipótese de clone semântico.
- Local A: src/billing.py, invoice_subtotal, linhas 4–8.
- Local B: src/billing.py, sum_net_prices, linhas 34–35.
- Abrangência: função inteira.
- Evidência: ambas acumulam, na ordem de iteração, item["price"] * item["quantity"], começando em zero.
- Justificativa: mesma computação aparente, com estruturas substancialmente diferentes (laço explícito versus expressão geradora entregue a sum).
- Limitações/falsos positivos: equivalência requer validação para tipos numéricos customizados, sobrecarga de __add__/__radd__, exceções e efeitos de acesso ao mapeamento.
- Confiança: Média.
- Sugestão: primeiro criar testes de caracterização; se passarem para os tipos admitidos, escolher uma única implementação de soma.
- Verificações propostas: lista vazia, inteiros, Decimal, float, iteradores de uso único, item com chave ausente e tipos numéricos customizados.

### CLONE-010 — contagem explícita versus materialização de lista

- Classificação: T4.
- Estado: hipótese de clone semântico.
- Local A: src/analytics.py, positive_count, linhas 4–9.
- Local B: src/analytics.py, positives_len, linhas 12–13.
- Abrangência: função inteira.
- Evidência: ambas avaliam number > 0 para cada elemento e retornam a quantidade de elementos que satisfazem o predicado.
- Justificativa: laço com contador e compreensão de lista seguida de len implementam a mesma intenção com estrutura diferente.
- Limitações/falsos positivos: a segunda versão materializa todos os positivos, portanto possui consumo de memória e falhas potenciais diferentes para entradas grandes; equivalência observável requer validação.
- Confiança: Média.
- Sugestão: preferir o contador explícito ou sum(1 for number in numbers if number > 0) se o objetivo for não materializar a lista.
- Verificações propostas: entrada vazia, gerador, entrada muito grande, números zero/negativos e iterável que lance exceção durante a iteração.

### CLONE-011 — soma embutida versus soma manual

- Classificação: T4.
- Estado: hipótese de clone semântico.
- Local A: src/analytics.py, total_sum, linhas 24–25.
- Local B: src/analytics.py, manual_total_sum, linhas 28–32.
- Abrangência: função inteira.
- Evidência: ambas iniciam efetivamente em zero e acumulam os elementos de numbers na ordem de iteração.
- Justificativa: sum(numbers) substitui sintaticamente o laço acumulador.
- Limitações/falsos positivos: classes numéricas customizadas, strings, operações de adição com efeitos e comportamento de exceções podem diferir.
- Confiança: Média.
- Sugestão: caracterizar o contrato aceito e, se ele for somente numérico convencional, padronizar em sum.
- Verificações propostas: sequência vazia, inteiros, float, Decimal, geradores, elementos não numéricos e objetos com __add__ customizado.

## Itens descartados

- src/permissions.py, linhas 4–25: predicados de uma expressão foram excluídos por serem triviais e por divergirem semanticamente nos operadores e limites.
- src/discounts.py, linhas 4–13: multiplicações de uma linha foram excluídas; as constantes representam políticas de desconto/imposto distintas.
- normalized_product_name em src/formatting.py, linhas 16–19: tem a mesma estrutura dos normalizadores, mas troca value por text; pode compor uma variante T2 do grupo CLONE-001, sem acrescentar uma duplicação independente acionável.
